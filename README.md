# agent-kit

One versioned batch of agent skills and plugin manifests that loads identically
in **Claude Code**, **Codex** and **OpenCode**.

Pin one version, verify one checksum, get the same skills in every harness.

## Status

Built at `0.1.0`. Seven skills, vendored and checksummed, observed loading in all
three harnesses from a single release artifact. See [PLAN.md](PLAN.md) for the
implementation brief and the recorded findings, and [AGENTS.md](AGENTS.md) for
the rules any agent working here must follow.

## Why it exists

The three harnesses discover skills from different directories and use three
incompatible plugin manifest formats, but they all read the same `SKILL.md`.
Without a shared source of truth the same skill gets copied three times and
drifts three ways.

No single directory serves all three harnesses:

| Path | Claude Code | Codex | OpenCode |
|---|:--:|:--:|:--:|
| `.claude/skills/` | yes | no | yes |
| `.agents/skills/` | no | yes | yes |

So a distribution writes to both. OpenCode reads both and deduplicates by skill
name, so the overlap costs nothing.

## The skills

| Skill | Upstream | What it is for |
|---|---|---|
| `writing-for-agents` | `mattpocock/skills` | Writing `AGENTS.md`, `CLAUDE.md` and skills; deletes no-op prose |
| `diagnosing-bugs` | `mattpocock/skills` | Diagnosis loop gated on a repro command that goes red first |
| `research` | `mattpocock/skills` | Primary sources only, writes a cited file |
| `tdd` | `mattpocock/skills` | Red-green-refactor at pre-agreed seams |
| `codebase-design` | `mattpocock/skills` | Deep-module vocabulary other skills borrow |
| `triage` | `mattpocock/skills` | Issue and external-PR state machine |
| `karpathy-guidelines` | `multica-ai/andrej-karpathy-skills` | Behavioural overlay against common LLM coding mistakes |

All MIT. Upstream commit and per-file sha256 for each are in
`agent-kit.lock.json`; upstream license texts ship in the artifact under
`licenses/`.

`triage` is deliberately explicit-invocation-only in Claude Code and Codex, so
Codex advertises six of the seven. That is upstream's instruction, not a
packaging fault; the lockfile records it per harness under `invocation`.

## Installing

### From a release (pin a version and a checksum)

```sh
gh release download v0.1.0 --repo janpuc/agent-kit --pattern 'agent-kit_*'
sha256sum --check agent-kit_0.1.0_checksums.txt
tar xzf agent-kit_v0.1.0.tar.gz
```

The extracted `agent-kit_v0.1.0/` is a working marketplace for both Claude and
Codex, and carries a self-contained plugin tree per harness:

```sh
claude plugin marketplace add ./agent-kit_v0.1.0
claude plugin install agent-kit@agent-kit

codex plugin marketplace add ./agent-kit_v0.1.0
codex plugin add agent-kit@agent-kit
```

For OpenCode, point `plugin` at the bundled shim:

```json
{ "plugin": ["/abs/path/to/agent-kit_v0.1.0/plugins/opencode/index.js"] }
```

### Straight from git

The repository root is itself the plugin for both Claude and Codex, so no
release round trip is needed:

```sh
claude plugin marketplace add janpuc/agent-kit
codex plugin marketplace add https://github.com/janpuc/agent-kit.git
```

### As plain directories

`dist/skills/` is the flat canonical set, for dropping into the two discovery
paths a provisioner needs:

- `$HOME/.agents/skills/<name>/` — Codex and OpenCode.
- `$CLAUDE_CONFIG_DIR/skills/<name>/` — Claude Code. `$CLAUDE_CONFIG_DIR` is the
  config root itself; appending `.claude` to it yields a path Claude does not
  read.

## Layout

- `skills/` — canonical `SKILL.md` trees. The only place a skill is authored.
- `vendor/` — verbatim upstream copies, one directory per upstream commit.
- `sources.json` — upstream coordinates. Hand-edited; the lockfile is generated.
- `plugins/opencode/` — npm shim that contributes the batch through its config hook.
- `.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/` — the repository root
  as a plugin and a marketplace for Claude and Codex.
- `dist/`, `release/` — generated by the build. Not committed.

## Working on it

```sh
just vendor        # refetch every pinned upstream into vendor/ and skills/
just lock          # regenerate agent-kit.lock.json
just build         # materialise dist/
just verify        # check dist/ against the lockfile
just package       # pack the release tarball and checksums
just ci            # everything CI runs, including the koment gates
```

Needs `just`, `koment` (both pinned in `mise.toml`) and Python 3.9+.

## Versioning

`VERSION` holds one semver for the whole batch. `agent-kit.lock.json` records,
per skill, the upstream repository, commit sha, license, per-file sha256, and any
recorded degradation. Releases ship `agent-kit_v<version>.tar.gz` alongside
`agent-kit_<version>_checksums.txt`. The tarball is byte-reproducible, so the
published sha256 identifies the content and not the machine that built it.
